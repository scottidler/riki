# TinaCMS learnings for riki

**Source:** `tinacms/tinacms`, branch `main`, commit `609d58b4`, cloned at `~/repos/tinacms/tinacms`. All paths below are relative to that repo unless marked **riki** (relative to `~/repos/scottidler/riki`) or **riki dep** (a file inside `editor/node_modules` at the versions riki's lockfile pins).
**Date:** 2026-10-02

## Framing

- TinaCMS is a headless CMS. Content lives in git as Markdown, MDX, JSON or YAML, typed by a user-written schema, and is served through a GraphQL API backed by a LevelDB-style index derived from the files (`packages/@tinacms/graphql/src/database/index.ts:74-110`). riki has no schema and no query layer: a page is a `.md` file and its URL.
- The editor is Plate (Slate), not ProseMirror. Markdown goes through micromark/remark into mdast, then into Slate JSON (`packages/@tinacms/mdx/src/parse/index.ts:74-99`), and back out through `mdast-util-to-markdown` (`packages/@tinacms/mdx/src/next/stringify/to-markdown.ts:62-66`). riki's Milkdown sits on the same mdast and `mdast-util-to-markdown` family (riki dep `mdast-util-to-markdown@2.1.3`), so Tina's serializer bugs are often riki's serializer bugs.
- Tina's round-trip bar is a fixed point, not byte identity. Its snapshot tests record rewrites as the expected output: `- this is a list item` comes back `* this is a list item` (`packages/@tinacms/mdx/src/next/tests/markdown-basic-autoformat-list-item-style/out.md:1`). riki refuses to edit any page whose no-edit serialization differs by a byte (riki `docs/design/2026-10-01-riki.md:148`).
- Every save rewrites the whole file, front matter included, and commits it through a pluggable `GitProvider` that receives only a path and the new bytes (`packages/@tinacms/graphql/src/database/index.ts:86-89`).
- What transfers is test design and a set of serializer edge cases, plus one search idea. The write path is an anti-pattern.

## What transfers

### Hard breaks: test the shape the editor produces

Tina found its hard-break corruptions by testing the tree the editor emits, not the tree a parser emits. riki's corpus tests only parser trees (no-edit round trips). A scratch vitest run against riki's own `makeEditor` (riki `editor/test/serialize.ts:5-26`, harness in the session scratchpad, nothing written to riki) applied the same edits as ProseMirror transactions:

| edit in riki's editor | serialized | Tina's handling |
|---|---|---|
| hard break replacing the space in `### one two` | `### one two\n` (break silently lost) | split into two headings |
| hard break in `# one two` / `## one two` | `one\\\ntwo\n===\n` / `---` (setext, a fixed point) | left as setext |
| hard break at the end of a paragraph, an H3, `**one**`, `[one](/x)` | unchanged, break dropped | dropped |

- **Heading split for H3 and deeper.** `###` and deeper have no setext form, so `mdast-util-to-markdown` writes the break as a space and the author's line break disappears with no error. Tina splits the heading at the break instead, keeping the level, so content and break both survive and the next save is a fixed point (`packages/@tinacms/mdx/src/break-serialization.ts:135-150`).
  - The cause in riki's serializer: `\n` is unsafe inside `headingAtx` (riki dep `mdast-util-to-markdown@2.1.3 lib/unsafe.js:41-50`), so `hardBreak` returns a space (riki dep `lib/handle/break.js:28-37`).
  - Milkdown already filters hard breaks out of `table` and `code_block` (riki dep `@milkdown/preset-commonmark@7.22.2 lib/index.js:2030`), but not out of headings. Adding a depth-3+ heading to that filter, or porting Tina's split, are the two options.
  - The split must recurse into the inline ancestor: a break inside link text in a heading needs the link copied onto both sides (`packages/@tinacms/mdx/src/break-serialization.ts:165-194`, test at `packages/@tinacms/mdx/src/break-serialization.test.ts:115-125`).
  - Trim trailing breaks over the whole tree before splitting, or the split leaves an empty link `### [](/x)` behind (`packages/@tinacms/mdx/src/break-serialization.ts:7-17`, test at `packages/@tinacms/mdx/src/break-serialization.test.ts:140-159`).
- **H1/H2 go setext on purpose.** `formatHeadingAsSetext` switches to setext whenever a heading below level 3 holds a break (riki dep `mdast-util-to-markdown@2.1.3 lib/util/format-heading-as-setext.js:19-38`). Tina keeps that shape because files already carry it (`packages/@tinacms/mdx/src/break-serialization.test.ts:218-232`). In riki the output is byte-stable (scratch run: `one\\\ntwo\n===\n` round-trips identical), but riki's canonical corpus has no setext heading at all, only the rewritten `setext-heading--equals` (riki `editor/fixtures/rewritten/setext-heading--equals.md`). Worth a canonical fixture so the shape the editor writes stays pinned.
- **Trailing breaks are already handled in riki.** Milkdown's `serializeText` drops a hard break that is the last child of a paragraph or heading (riki dep `@milkdown/preset-commonmark@7.22.2 lib/index.js:32-43`, used at `:551` and `:652`). Because ProseMirror marks are flat, a break inside a trailing bold or link is still the block's last child, so Tina's nested cases (`packages/@tinacms/mdx/src/break-serialization.ts:54-87`) don't arise. A second Shift+Enter at the end of a block turns the break into a new paragraph (riki dep `lib/index.js:1121-1129`).
- **Line-start neighbours.** A break puts what follows at the start of a line. Tina lost content when that neighbour was `<` or an inline component (`packages/@tinacms/mdx/src/break-serialization.ts:97-130`, `packages/@tinacms/mdx/src/break-neighbours.test.ts:6-10`). In riki the scratch run shows `one\\\n<em>x</em>\n` round-tripping identical; a canonical fixture would keep it that way.

### Mark whitespace

- A mark that covers only whitespace corrupts content in riki today. Scratch run: a strong mark over the single space in `Some word more` serializes to `Some**** word more\n`. Reloaded, `****` is literal text, and the next serialization writes `Some\*\*\*\* word more\n`. The guard refuses that page on its next load, so it becomes non-editable in the browser and holds four asterisks nobody typed.
- Tina's fix drops the markers from a mark left empty once its edge whitespace moves out (`packages/@tinacms/mdx/src/stringify/mark-whitespace.ts:72-77`), tested at `packages/@tinacms/mdx/src/stringify/mark-whitespace.test.ts:172-183`. It runs on the mdast before `toMarkdown` (`packages/@tinacms/mdx/src/next/stringify/index.ts:15`), which in riki is a `$remark` transform or a serializer-side check in `makeEditor` (riki `editor/src/setup.ts:79-108`).
- Milkdown already moves edge whitespace out of a non-empty mark: the same run writes `Some **word** more\n` for a strong mark over `word ` or ` word`. Tina had to build that hoist itself (`packages/@tinacms/mdx/src/stringify/mark-whitespace.ts:99-117`). Raw `mdast-util-to-markdown` would encode the space instead (`Some **word&#x20;**&#x6D;ore`, scratch run against riki dep `mdast-util-to-markdown@2.1.3`), so the hoist is Milkdown's, and a fixture pinning it guards against a Milkdown upgrade.
- Tina also clears hoisted whitespace at a block or table-cell edge, because there it reloads as indentation or widens a column on every save (`packages/@tinacms/mdx/src/stringify/mark-whitespace.ts:7-13`, `:87-93`).

### Fixture candidates from Tina's corpus

Each input below came from a Tina test and was run through riki's `roundTrip` in the scratch harness. "Canonical" means byte-identical and a fixed point; "rewritten" means a fixed point that differs.

- **Canonical, missing from riki's set** (riki `editor/fixtures/canonical/`):
  - escaped block starts `\# not a heading`, `\> not a quote`, `\- not a list` (from `packages/@tinacms/mdx/src/next/tests/markdown-basic-escapes/in.md:3-13`)
  - image inside a link `[![alt](/i.png)](/x)` (from `packages/@tinacms/mdx/src/next/tests/markdown-basic-image-in-link/in.md:1`)
  - hard break inside a link, a blockquote and a list item (shapes from `packages/@tinacms/mdx/src/break-representability/markdown.md:30,34,52`); riki has only the paragraph case (riki `editor/fixtures/canonical/hard-break--backslash.md`)
  - a task list mixed with plain items, and an ordered task list (Tina's no-checkbox case, `packages/@tinacms/mdx/src/task-list.test.ts:54-61`)
  - non-ASCII text: emoji ZWJ sequences, skin tones, CJK, RTL (from `packages/@tinacms/mdx/src/next/tests/markdown-basic-unicode/in.md:1-18`)
  - `***bold and emphasized***` (from `packages/@tinacms/mdx/src/next/tests/markdown-basic-marks/in.md:3`)
  - the setext-with-break heading above
- **Rewritten, missing from riki's set** (riki `editor/fixtures/rewritten/`):
  - `\\` (escaped backslash) comes back `\`; Tina's snapshot records the same rewrite (`packages/@tinacms/mdx/src/next/tests/markdown-basic-escapes/out.md:7`)
  - `\|` in plain text comes back `|`, and `C:\\path` in a table cell comes back `C:\path` (Tina: `packages/@tinacms/mdx/src/next/tests/markdown-basic-tables-escapes/out.md:4`)
  - `\[not a link\](https://example.com)` comes back `\[not a link]\(<https://example.com>)`: the GFM literal autolink turns the URL into a link node. Tina gets the same autolink, written as `[url](url)` (`packages/@tinacms/mdx/src/next/tests/markdown-basic-escapes/out.md:5`)
  - marks inside link text flip outside it: `[**a**](/x)` comes back `**[a](/x)**`, `[_b_](/y)` comes back `_[b](/y)_`. Tina's link-children inputs (`packages/@tinacms/mdx/src/link-children.test.ts:26-33`) surfaced it
  - `- [X] done` comes back `- [x] done`
- **Code fence meta.** riki already lists it as rewritten (riki `editor/fixtures/rewritten/code-fence-style--meta.md`). Milkdown's `code_block` keeps only `language` (riki dep `@milkdown/preset-commonmark@7.22.2 lib/index.js:849`, parse at `:881-883`, write at `:891`), so `js {1,3-5}` loses `{1,3-5}`. Tina carries `meta` as an editor attribute end to end (`packages/@tinacms/mdx/src/parse/plate.ts:28-34`, `packages/@tinacms/mdx/src/parse/remarkToPlate.ts:303`, `packages/@tinacms/mdx/src/next/stringify/pre-processing.ts:82`) and round-trips it (`packages/@tinacms/mdx/src/next/tests/markdown-basic-code-block-meta/out.md:1-7`). An `extendSchema` on `code_block`, the same mechanism the table-alignment fix uses (riki `docs/design/2026-10-02-riki-wiki-operations.md:184`), would move it to canonical.

### Coverage keyed on the schema, not on a list

- Tina's break matrix is a `Record` keyed on the editor's block and inline type unions, so adding an element type fails typecheck until someone says what a break does inside it. Its comment says earlier fixes each kept a partial hand list and regressed a container they had not thought of (`packages/@tinacms/mdx/src/break-representability/index.test.ts:10-21`, records at `:48-82`).
- riki's coverage check is keyed on the Phase 0a failure-histogram categories (riki `editor/test/fixtures.test.ts:13-39`, checked at `:81-96`). A Milkdown plugin that adds a node type passes it without a fixture. A test that every node and mark in the loaded schema appears in at least one canonical fixture would close that; `nodeNames` already walks the loaded doc (riki `editor/test/serialize.ts:29-38`) but collects nodes only, not marks.
- Two more axes Tina added after the type axis missed bugs: nesting combinations (`packages/@tinacms/mdx/src/break-representability/index.test.ts:104-113`) and the neighbour after the edit (`:84-102`).
- Build test trees by parsing Markdown and injecting the edit, not by writing node literals, because a wrong literal produces empty output that reads as a finding (`packages/@tinacms/mdx/src/break-representability/index.test.ts:36-43`, inject at `:161-192`).
- Each row checks three properties separately: it parses, it is a fixed point, and the second save doesn't throw. Bytes alone call a dangling `\` a pass, because it reads back as text (`packages/@tinacms/mdx/src/break-representability/index.test.ts:232-242`). riki's rewritten suite checks the fixed point (riki `editor/test/fixtures.test.ts:110-115`) and marks lossy rewrites by hand (riki `editor/test/fixtures.test.ts:69`). A per-type node count before and after, like Tina's `breaks` column (`packages/@tinacms/mdx/src/break-representability/index.test.ts:194-204`), would flag a lossy rewrite without the hand list.
- The matrix is a committed snapshot that records current behaviour, broken rows included; a fix flips rows in the snapshot (`packages/@tinacms/mdx/src/break-representability/index.test.ts:19-20`, snapshot `packages/@tinacms/mdx/src/break-representability/markdown.md:1-73`). That gives riki a cheap way to track edit-path shapes like the ones in the hard-break table.

### Search: typo tolerance and incremental reindex

riki's search shipped as a prefix-matching in-memory index rebuilt on every publish (riki `docs/design/2026-10-02-riki-wiki-operations.md:121-129`, decision at `:333`).

- **Fuzzy fallback.** Tina expands each query term against the index dictionary: prefix matches first, then Damerau-Levenshtein within distance 2 and similarity 0.6, with a bigram-overlap prefilter and at most 10 expansions (`packages/@tinacms/search/src/fuzzy/distance.ts:126-187`, defaults at `packages/@tinacms/search/src/fuzzy/types.ts:21-30`). Expansions become `OR` groups under the original `AND` (`packages/@tinacms/search/src/fuzzy-search-wrapper.ts:110-123`). riki's `BTreeMap` keys are that dictionary already, so a fallback when a prefix finds nothing needs no new structure. riki's design doesn't mention typo tolerance.
- **Stopwords on multi-word queries only.** Tina drops stopwords and `and` when the query has more than one word, and keeps a one-word query as typed (`packages/@tinacms/search/src/index-client.ts:67-84`). Under riki's all-terms-must-match rule, a query like "how to deploy" needs a page with a term starting "to".
- **Incremental by tree diff.** Tina's partial reindex stores the last indexed commit as `lastSha` metadata, diffs that tree against `HEAD` by comparing blob oids per path, and reindexes only added and modified paths and deletes removed ones (`packages/@tinacms/cli/src/next/commands/baseCommands.ts:163-215`, diff at `packages/@tinacms/graphql/src/git/index.ts:57-94`). It falls back to a full reindex when the schema file changed (`packages/@tinacms/cli/src/next/commands/baseCommands.ts:190-199`) or the old commit object is gone (`packages/@tinacms/graphql/src/git/index.ts:98-110`).
  - A tree-to-tree diff is valid between any two commits, so unlike riki's redirect walk (riki `docs/design/2026-10-02-riki-wiki-operations.md:235`), a per-page index needs no ancestor check, only both trees.
  - This applies to Tina's GraphQL index. Its search index is rebuilt in full on startup (`packages/@tinacms/cli/src/next/commands/dev-command/index.ts:211-217`) and updated per file only by the dev-mode file watcher (`:354-428`).
  - riki logs build time and sets no bound until a corpus needs one (riki `docs/design/2026-10-02-riki-wiki-operations.md:373`). Per-page sections keyed by blob oid plus this diff is the path when it does.

### Link URL sanitizing

- Tina strips Unicode control (`Cc`) and format (`Cf`) characters before testing a URL for a scheme, because the URL parser drops tab and newline anywhere, so `java<TAB>script:` reaches a browser as `javascript:`, and zero-width characters hide a scheme from a reader (`packages/@tinacms/mdx/src/sanitize-url.ts:10-31`). A URL that fails to parse but still names a scheme is rejected, not passed through (`:39-53`).
- riki's link box inserts input that parses as an absolute URL as-is (riki `docs/design/2026-10-02-riki-wiki-operations.md:176`) and relies on comrak's safe mode at render (riki `docs/design/2026-10-01-riki.md:117`). A golden HTML test with those disguised schemes would show whether comrak catches them; this doc did not test comrak.

## What it confirms riki already has right

- **Optimistic writes with a base oid.** Tina's GitHub provider fetches the file's current sha at write time and passes it straight to `createOrUpdateFileContents` (`packages/tinacms-gitprovider-github/src/index.ts:36-60`). Verified: the sha is the tip's at the moment of the write, never the version the editor loaded, so two editors on one page both succeed and the second silently overwrites the first. Last writer wins. Details:
  - A failed lookup is swallowed (`catch (e) {}`, `packages/tinacms-gitprovider-github/src/index.ts:50`), and delete does the same (`:66-77`).
  - The `GitProvider` interface carries only `(key, value)` (`packages/@tinacms/graphql/src/database/index.ts:86-89`), so no provider could check a base version without an interface change. A search of `@tinacms/graphql/src`, `@tinacms/datalayer/src` and the GitHub provider for `409`, `If-Match` or a base sha finds no other concurrency check.
  - riki's save compares the tip blob with the client's base oid and answers 409 with the current body (riki `core/src/save.rs:122-132`, design `docs/design/2026-10-01-riki.md:205-209`).
- **Commit identity.** Tina commits every edit as the token owner with the message `Edited with TinaCMS` unless configured (`packages/tinacms-gitprovider-github/src/index.ts:56`). riki commits with the user as author (riki `docs/design/2026-10-01-riki.md:211`).
- **Index before push.** Tina writes the file through the bridge and the git provider, then computes the index operations (`packages/@tinacms/graphql/src/database/index.ts:565-600`), so a failure there leaves git ahead of the index. riki builds the nav index for the new commit before pushing and pushes nothing on an index error (riki `docs/design/2026-10-01-riki.md:212`).
- **Front matter untouched.** Tina re-dumps front matter through `js-yaml` `safeDump` on every save (`packages/@tinacms/graphql/src/database/util.ts:110-132`), which drops comments and quoting style, and had to disable gray-matter's JavaScript and CoffeeScript engines because they execute code (`packages/@tinacms/graphql/src/database/util.ts:21-32`). riki never sends front matter to the editor and re-attaches the tip blob's bytes (riki `docs/design/2026-10-01-riki.md:145-146`).
- **CR refused, not normalized.** Tina turns CRLF into LF on parse (`packages/@tinacms/mdx/src/parse/index.ts:155-159`, tested at `packages/@tinacms/mdx/src/line-endings.test.ts:32-36`), so the first save of a CRLF file rewrites every line. riki makes any file with `\r` non-editable (riki `core/src/page.rs:96-106`).
- **Whole-page fail-closed.** When Tina can't parse a field it shows the whole field as one `invalid_markdown` node instead of editing a partial tree (`packages/@tinacms/mdx/src/parse/index.ts:201-229`); its own test notes that a gap in one construct costs the whole document (`packages/@tinacms/mdx/src/link-children.test.ts:6-11`). riki does the same per page: a page that fails the guard stays readable and editable via git (riki `docs/design/2026-10-01-riki.md:148`).
- **Search reads the whole section.** Tina's indexer keeps only the first `textIndexLength` characters of each field, 500 by default (`packages/@tinacms/search/src/indexer/index.ts:39`, cutoff in `packages/@tinacms/search/src/indexer/utils.ts:22-28`), and the CLI passes 100 when the config sets nothing (`packages/@tinacms/cli/src/next/commands/dev-command/index.ts:207-208`, `packages/@tinacms/cli/src/next/commands/searchindex-command/index.ts:99-100`). Its tokenizer splits only on whitespace, `.` and `,` (`packages/@tinacms/search/src/indexer/utils.ts:35-40`), so `foo-bar` and `(note)` stay single tokens. riki indexes every section's full text and splits on anything non-alphanumeric (riki `docs/design/2026-10-02-riki-wiki-operations.md:123-125`).
- **Serializer options chosen, not defaulted.** Tina passes only `listItemIndent: 'one'` (`packages/@tinacms/mdx/src/next/stringify/to-markdown.ts:62-66`), so every `-` list comes back `*` and its snapshots accept the churn. riki picked `bullet: '-'` and `rule: '-'` by measuring strict-pass on its corpus (riki `editor/src/setup.ts:56-63`, riki `docs/design/2026-10-01-riki.md:298`).
